# دليل العرض المحلي

هذا عرض لنسخة تجريبية تجيب عن سياسة عطور وتجهز مسودات فقط. الربط مع Gemini حقيقي عند استخدام مفتاحك، لكن لا يوجد تكامل ينشئ طلبًا في متجر أو ينفذ استردادًا ماليًا.

## قبل العرض

اتبع إعداد البيئة وتشغيل الخادم في [README](../README.md)، من جذر نسخة التسليم. افتح [واجهة API](http://127.0.0.1:8001/docs). استخدم بيانات تجريبية فقط، ولا تعرض مفتاحك أو ملف `.env`.

شغّل الاختبارات المحلية أولًا إن أردت فحص النسخة دون استهلاك حصة Gemini:

```powershell
.\.venv\Scripts\python.exe .\scripts\run_tests.py
```

الخطوات التالية دليل تنفيذ، وليست ادعاء بأنها نُفذت اليوم. سجّل النتائج الفعلية في [VERIFICATION](VERIFICATION.md) دون نسخ أسرار أو بيانات عملاء.

## 1. هل الواجهة تعمل؟

افتح `GET /health` ثم **Try it out → Execute**. النتيجة المنتظرة:

```json
{"status": "ok"}
```

هذا يفحص خادم API فقط؛ لا يثبت أن Gemini متاح أو أن الإجابات صحيحة.

## 2. سؤال له دليل في السياسة

في `POST /ask` أرسل:

```json
{"user_input": "ما مهلة تقديم متابعة لعطر وصل مكسورًا؟"}
```

راجع الجواب نفسه، ثم `sources`: المهلة في الوثيقة الحالية **3 أيام من الاستلام**، والمقطع `p1-c1` من صفحة 1 يتضمن الدليل. قد تختلف صياغة Gemini، ولا يكفي ظهور `success` وحده لإثبات صحة النص. افتح نص المصدر وتأكد من أنه يدعم الجواب.

## 3. سؤال غير موجود في السياسة

جرّب السؤال الآتي في `/ask`:

```json
{"user_input": "هل توصلون الطلبات إلى جدة؟"}
```

المتوقع `status: insufficient_evidence` ومصادر فارغة `sources: []`. هذا امتناع مقصود، لا خطأ شبكة، ولذلك يمكن أن يكون HTTP `200`. لو اختلق النموذج سياسة توصيل، سجّل الحالة كفشل ولا تعتبر المراجع وحدها نجاحًا.

## 4. مدخل مرفوض قبل Gemini

في `/ask` أرسل:

```json
{"user_input": "   "}
```

المتوقع HTTP `422` ورسالة «النص مطلوب». هذا فحص للمدخلات، ولا يحتاج اتصالًا بالنموذج. أما HTTP `500` فيعني فشلًا يعالجه التطبيق، مثل مشكلة في المفتاح أو الفهرس أو خدمة التوليد؛ لا تحوّله إلى رسالة نجاح.

## 5. مسودة وليست طلبًا منفذًا

في `POST /requests` أرسل بيانات وهمية:

```json
{"user_input": "طلبي رقم 5، عطر عساف وصل والعبوة مكسورة"}
```

راجع `status: draft` ومحتوى `data`. وجود رقم الطلب في المسودة لا يثبت وجوده في متجر، ولا يعني قبول الاستبدال. هذه تجربة توليد إضافية تستهلك حصة Gemini، وليست خطوة لازمة لفحص `/health` أو الاختبارات المحلية.

## n8n اختياري

اتبع [دليل التدفق](../customer_support_agent/automation/N8N_DEMO.md). التسلسل هو تشغيل يدوي، ثم إعداد السؤال، ثم HTTP Request إلى `/ask`. جرّب السؤال المدعوم والسؤال خارج الوثيقة والمدخل الفارغ إذا أردت فحص الحالات الثلاث.

دور n8n هو إرسال السؤال وعرض نتيجة API؛ التطبيق الخلفي هو الذي يسترجع المقاطع ويتصل بـGemini. لا يُحفظ مفتاح Gemini في التدفق. نجاح التدفق لا يمنح صلاحيات إنشاء طلبات أو دفع، وهو غير منشور أو مجدول تلقائيًا.

## شرح قصير أثناء العرض

«نقرأ سياسة PDF ونقسمها إلى مقاطع لها معرفات وصفحات. نحول سؤال العميل إلى متجه، ونسترجع المقاطع الأقرب، ثم نطلب من النموذج الإجابة منها. نتحقق من معرفات المراجع محليًا ونمتنع عندما لا يكفي الدليل. المسار الآخر يجهز مسودة منظمة فقط، وn8n يربط واجهة التدفق بـAPI المحلية».

النسخة أُنجزت بمساعدة تدريبية وتنفيذية. نتائجها المحلية لا تثبت جاهزية إنتاجية أو اجتياز تقييم مستقل. الحالات العشرون الأصلية لم تُنفذ، ولا يتضمن هذا التسليم ادعاء اجتياز Gates.
