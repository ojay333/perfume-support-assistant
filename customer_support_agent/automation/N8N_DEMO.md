# n8n — تجربة محلية محدودة

الهدف: تشغيل تدفق واحد يرسل سؤالًا إلى API مشروع العطور الموجود، دون إعادة كتابة قواعده ودون صلاحية إنشاء طلب متجر أو تنفيذ دفع.

## التدفق

1. `Manual Trigger`: يبدأ فقط عند تشغيل التدفق يدويًا.
2. `Question`: يحفظ نص السؤال في `user_input`؛ يمكن تعديل هذه القيمة للتجربة.
3. `Ask local API`: يرسل `POST` إلى `http://127.0.0.1:8001/ask`، ويأخذ نص السؤال من العقدة السابقة.

إعداد جسم الطلب:

```javascript
{{ JSON.stringify({ user_input: $json.user_input }) }}
```

`$json.user_input` هو الحقل القادم من العقدة السابقة. يحوّله التعبير إلى جسم JSON يفهمه FastAPI. لا يوجد مفتاح Gemini في ملف التدفق؛ التطبيق الخلفي هو الذي يتصل بالخدمة.

## متطلبات التشغيل

- API المشروع تعمل محليًا على المنفذ `8001`، مع فهرس صالح ومفتاح Gemini محلي لا يُشارك.
- إصدار التجربة `n8n 2.41.3`، ويتطلب `Node.js >= 24`. لا حاجة إلى Docker أو حساب سحابي لهذا المثال.
- الملف `n8n-policy-demo.json` قابل للاستيراد؛ يبقى غير منشور وغير مفعّل تلقائيًا.

من جذر نسخة التسليم، بعد إعداد البيئة كما في README، شغّل API:

```powershell
.\.venv\Scripts\python.exe -m uvicorn api:app --app-dir customer_support_agent --host 127.0.0.1 --port 8001
```

في نافذة أخرى، إذا لم تكن لديك نسخة n8n محلية مثبتة، يمكن تشغيل النسخة المحددة بعد تنزيلها:

```powershell
$env:N8N_LISTEN_ADDRESS = "127.0.0.1"
$env:N8N_DIAGNOSTICS_ENABLED = "false"
npx n8n@2.41.3 start
```

قد يستغرق التنزيل الأول وقتًا. افتح `http://127.0.0.1:5678`، وأكمل إعداد المالك المحلي بنفسك إن طُلب، ثم استورد ملف التدفق. لا تشارك كلمة المرور أو ملفات بيانات n8n. برنامج n8n وبيانات حسابه المحلي غير مضمنين في نسخة التسليم.

## كيف تفحص النتيجة؟

- سؤال موجود في السياسة: `statusCode: 200`، وداخل `body` إجابة `success` مع `sources`.
- سؤال لا يوجد جوابه في الوثيقة: HTTP `200`، لكن `body.status` هو `insufficient_evidence`؛ هذا امتناع مقصود لا فشل اتصال.
- غيّر سؤال `Question` إلى مسافات: يرفض FastAPI المدخل برمز `422`، وتفشل عقدة HTTP. لا تغيّر الإعداد لتجاهل الخطأ واعتباره نجاحًا.
- إذا توقفت API، يجب أن ترى خطأ اتصال في عقدة HTTP؛ لا توجد إعادة محاولة آلية في هذا التدفق.

كل سؤال صالح يستدعي Gemini عادة مرتين عبر التطبيق الخلفي (متجه السؤال ثم توليد الرد). المدخل المرفوض لا يحتاج استدعاء النموذج.

## حدود العرض

هذه تجربة محلية صغيرة، وليست نظام أتمتة إنتاجيًا أو تكامل متجر أو اجتيازًا لـGate 21. إنشاء التدفق بمساعدة لا يثبت فهمًا مستقلًا؛ ينبغي أن تستطيع تعديل السؤال، وشرح انتقاله إلى API، وتمييز الإجابة والامتناع والخطأ.

حالة التحقق في 30 سبتمبر 2026: استُورد التدفق داخل n8n 2.41.3 ونُفذ فعليًا من سطر الأوامر. نجحت العقد الثلاث، ووصل POST إلى خادم FastAPI المحلي، وأعاد HTTP 200 وجواب 3 أيام مع المصدر `p1-c1` / صفحة 1. استغرق طلب HTTP حوالي 2.85 ثانية في تشغيل واحد، واستهلك استدعاءين إضافيين لـGemini.

استُوردت نسخة اختبار منفصلة بسؤال مكوّن من مسافات. نجحت عقدتا البداية وإعداد المدخل، ثم فشلت عقدة HTTP برمز 422 ورسالة «النص مطلوب»، وسُجل تنفيذ n8n بحالة `error`. هذا فشل متوقع وصحيح لا نجاح شكلي، ولم يُستدعَ Gemini للمدخل المرفوض.

جُربت واجهة تحرير n8n في عرض موجه يوم 30 سبتمبر بعد إعداد حساب المالك المحلي. ظهر جواب ناجح مع المصدر، وأُبلغ عن امتناع لسؤال التوصيل إلى جدة ورسالة «النص مطلوب» لمدخل المسافات؛ لم يوثق تقرير الواجهة رقم 422 نفسه. الرقم مثبت في اختبار سطر الأوامر المنفصل أعلاه. وفي 1 أكتوبر، نجح فحص موجه لـ`/health` وسؤال المهلة من Swagger مع جواب 3 أيام ومصدر `p1-c1` / صفحة 1. هذه أدلة تشغيل موجه، وليست إثبات إعادة تشغيل مستقلة من بيئة نظيفة. راجع سجل التحقق في `docs/VERIFICATION.md` بجذر نسخة التسليم لحالة الفحص الأحدث.

قد يظهر تحذير في هذه البيئة عن عدم توفر Python task runner الخاص بـn8n. هذا التدفق لا يستخدم عقدة Python؛ نجحت عقده اليدوية وSet وHTTP دونها. لا حاجة إلى تثبيت بيئة أخرى لهذا المثال، ولا يعني التحذير أن Python الخاص بمشروع FastAPI معطل.
